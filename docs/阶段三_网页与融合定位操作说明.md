# 阶段三：网页、FAST-LIO＋视觉定位、导航至楼梯

适用目录：`/home/robot/zhangzhang/d1_stair_nav_phase3_orin_scan_axisfix_20261116`，ROS 2 Humble。2026-11-15 更新。

FAST-LIO 一直参与连续定位；视觉负责初始地图定位和纠偏；Nav2 负责下层平面导航。AMCL 不参与。原 Stair 上楼、人工确认与楼层交接逻辑保留。网页只观察，无运动控制。

## 1. 打开网页与定位

Windows PowerShell（保持此窗口连接；已有 SSH 配置别名 `orin`）：

```powershell
ssh -L 8767:127.0.0.1:8767 orin
```

不使用别名时，等效命令为：

```powershell
ssh -J robot@10.196.164.98 -L 8767:127.0.0.1:8767 robot@192.168.168.100
```

进入 Orin 后：

```bash
cd /home/robot/zhangzhang/d1_stair_nav_phase3_orin_scan_axisfix_20261116
source scripts/env_live.sh
python3 scripts/sensor_stack.py start
python3 scripts/sensor_stack.py status
bash scripts/run_web.sh
```

电脑浏览器打开 <http://127.0.0.1:8767>。网页前台运行，使用其他命令时另开 SSH 终端；每个 Orin 终端均先 `cd` 到上述目录并 `source scripts/env_live.sh`。不需要 WSL 或 RViz。

首次加载这次更新前，若旧版定位进程仍在运行，先在狗停稳、导航和上楼任务均已结束后执行一次 `python3 scripts/sensor_stack.py stop`，再 `start`，使进程加载新代码。运行中不要用这两条命令刷新页面。

`sensor_stack.py start` 启动 FAST-LIO、视觉融合、点云转障碍扫描。相机和原始雷达由狗上已有服务提供；本脚本不负责打开硬件驱动。`preflight.py` 是检查工具，不是传感器启动器。

## 2. 看懂页面，确认地图位置

- 绿色箭头：融合定位就绪；蓝色箭头：已保存楼梯预备点。原坐标保留为 x=1.924587、y=-0.328061、yaw=0.094410 rad。页面会自动读取，无需再点一次标记。
- 橙色：按旧地图对齐继续用 FAST-LIO 推算，只供参考，导航不就绪；灰色：最后已知位置或网页断线。
- 红点：新鲜且时间对齐的障碍扫描；紫线：收到的近期 Nav2 规划。无有效融合定位时红点不叠加。
- 上层选项只换底图，不切换任务楼层。网页不代替 RViz 的完整 TF、代价地图调试功能。

狗必须回到当前地图采集场景，且相机能看到建图时的区域，才能完成初始视觉确认。地图坐标本身不因光照改变，但视觉识别会受光照、视角、遮挡影响。FAST-LIO 不能凭空确定自己在旧地图中的绝对位置。

首次定位需要 2 秒内 3 个不同时间戳的一致候选。视觉偶尔失败时 FAST-LIO 继续推进；超过 5 秒没有可靠视觉纠偏，或纠偏超过 0.15 m / 5°，撤销就绪并要求停稳重定位。这些阈值是保守调试起点，仍需现场验证。

查看完整状态、日志：

```bash
ros2 topic echo /d1/localization/status --once --full-length
tail -n 20 work/visual_diagnostics.jsonl
tail -n 30 work/localization.log
```

需要重新定位时，先结束当前导航或上楼任务，现场确认狗停稳、处于非 Stair 状态；静止至少 2 秒，然后：

```bash
python3 scripts/relocalize.py --confirm-stopped
```

此命令不会替你停车。它检查停稳和控制任务状态，最多等待约 30 秒重新获取三帧确认；失败会给原因。成功后再次核对网页位置，再启动新的导航任务。不要在楼梯上执行。

## 3. 需要改预备点时才重新标定

旧点已保留，不因狗开走或软件重启而失效。先核对蓝色点是否对应真实楼梯前的平整预备区，方向是否朝向楼梯；它应能容纳整狗停稳和切步态，不应卡在第一阶边缘。

若确需改点：人工将狗带到预备区并对正，在绿色定位、狗停稳时执行：

```bash
python3 scripts/capture_entry.py --confirm-lower-entry
```

这条命令把当时狗的位置和朝向写入 `config/site.yaml`，网页随后更新蓝色箭头；不会控制狗移动。它会清除旧的地图/扫描检查记录。不要在网络恢复后的其他位置误执行，否则会覆盖入口。

## 4. 验证平面导航，再接上楼

先核对当前绿色位置、地图墙体、红色扫描与现场一致，蓝色点及方向正确，狗的 footprint 和预备区相容；确认后才记录人工检查：

```bash
python3 scripts/validate_site.py --confirm-map-and-scan
```

该命令只记录你的检查，不会自动证明地图正确。当前交付的检查标记保持 false。完成实际检查前，Nav2 启动会被拒绝。

一次性依赖检查/构建（本次已在 Orin 构建通过，新解压或改 C++ 后再执行）：

```bash
bash scripts/check_dependencies.sh
bash scripts/build.sh
```

终端 A（SDK 桥接，IP 是机器人控制端，不是 Orin）：

```bash
bash scripts/run_stair_bridge.sh 192.168.168.168 0.5
```

终端 B（Nav2）：

```bash
bash scripts/run_nav2.sh floor:=lower
```

终端 C（先只验证自动走到点并停稳）：

```bash
bash scripts/run_mission.sh --live --approach-only
```

终端出现 `HANDOFF: entry reached and stopped` 和 `DONE: 已停在预备点，本次不切换 Stair。`，表示监督程序检查通过。还需现场核对狗位置与朝向；网页“几何接近”不能代替任务成功和停稳确认。若 FAULT，先看原因，不要跳过。

平面验收后，下一次完整任务改用：

```bash
read -p "请输入已验证的最大前进秒数：" STAIR_SECONDS
bash scripts/run_mission.sh --live --duration "$STAIR_SECONDS"
```

狗到点停稳、SDK 确认 Stair 后，终端等待人工输入。本项目现有 `stair_start.py` 要求输入 **`y 0.5`** 后回车；只输入 `y` 会取消。这沿用 Orin 当前代码格式，和早期包可能不同。目标速度 0.5 m/s，桥接上限也是 0.5。最大时长是控制上限，不能自动判断已经到上层平台。原楼层交接方式保持不变。

## 6. 视觉匹配阈值更新

本版吸收 FRONT_A 独立定位包中“匹配阈值可配置、逐候选输出失败原因”的做法。`config/runtime.yaml` 默认 `matching_profile: relaxed`，只用于启动时建立地图初始位姿；三帧确认完成后，后续视觉纠偏及显式重定位继续使用原 `strict` 门限。设为 `strict` 则初始定位也恢复原门限。

FRONT_A 包中的视觉库/数据库和预备点属于它自己的地图坐标系。本次没有导入或替换它们；本项目继续使用 `site_identity.json` 绑定的 retained 视觉库、相机标定、lower/upper 栅格地图和当前入口坐标。若将来决定换用 FRONT_A 地图，必须重新确认地图间坐标变换并重新测量入口点，不能直接复制它的点坐标。

如需切回旧的严格筛选，在没有导航/上楼任务且狗已停稳时执行：

```bash
python3 scripts/sensor_stack.py stop
nano config/runtime.yaml
# 将 matching_profile: relaxed 改为 matching_profile: strict，保存退出
python3 scripts/sensor_stack.py start
```

正常启动仍使用 `sensor_stack.py start`，它会读取上述默认配置。诊断写入 `work/visual_diagnostics.jsonl`，包含候选 votes、匹配数、PnP 内点/比例、重投影误差、图像覆盖范围和拒绝原因。

初始阶段的 `relaxed` 仍要求至少 12 个唯一匹配和 12 个 PnP 内点、内点比例不低于 0.20、重投影误差不高于 4 px、内点覆盖达到设定下限，并检查正深度与图像分布。它没有采用 FRONT_A bootstrap 中较宽松的“两帧、1 米、30°”确认。融合层原来的 2 秒窗口三帧一致确认、帧间隔、0.25 m / 10° 跳变拒绝、视觉过期失效、FAST-LIO 连续传播及停稳后显式重定位均未更改。

验证边界：当前地图的 8 个关键帧同次采集自测中，严格配置通过 6/8，宽松配置通过 7/8；新增通过的样本仍只有 13 个内点。这不是独立采集或现场实机验证。另一组 51 张独立图片此前在严格阈值及 CLAHE 下均未通过。此次代码尚未部署到 Orin，不能据此认为初始定位问题已在实机解决。请先在原地图采集场景、机器人静止且环境安全时测试网页定位；如果位置不稳定或诊断显示错误候选通过，停止导航并反馈日志，不要直接运行 Nav2 或上楼任务。
