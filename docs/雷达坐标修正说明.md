# 雷达坐标修正说明

本版先撤销上一版本的 X/Y 交换。只交换 X/Y 会把原始雷达的竖直轴和水平轴混在一起。

在 Orin 上只读采样得到：

- `/front_lidar` 原始点云的地面主平面法向约为原始 `-X`；
- `/front_lidar/imu` 静止加速度主要沿 `+Y`；
- 当前 FAST-LIO 世界坐标因此采用 Y-up 约定；
- 标定外参 `base <- LiDAR` 将原始 LiDAR `-X` 映射为机身竖直方向，原始 `Z` 为前向方向。

本版只在 `scripts/cloud_scan.py` 的二维雷达投影中增加测得的基准转换：

`nav_x = -lio_z`，`nav_y = -lio_x`，`nav_z = lio_y`。

之后仍使用原始点云轴顺序和原标定 `base <- LiDAR` 外参，不修改视觉定位、FAST-LIO、相机、地图、导航参数或楼梯控制。

## 影响范围

这项修改只影响 `/d1/nav/scan` 及网页显示的实时障碍点。视觉回环使用相机和视觉库，FAST-LIO 使用自身的点云/IMU融合与 `/Odometry`，均没有改动。因此不会改变视觉回环或 FAST-LIO 的算法结果。

现场仍需确认：机器狗停在平地时，网页/RViz 中地面不应形成一侧连续障碍；前方和左右放置单个障碍物时，扫描方向应分别落在对应方向。若视觉或 FAST-LIO 的地图坐标也出现轴向问题，应另行检查 `/Odometry` 的世界坐标约定，不能通过修改雷达投影掩盖。
