# 已从代码确定的内容和仍缺少的数据

已核实：SDK 0.2.1、Stair()、Move()；ROS 2 Humble / Ubuntu 22.04；机器人默认 IP 192.168.168.168:8082；FAST-LIO /Odometry、前雷达 /front_lidar、雷达 IMU /front_lidar/imu、RGB /front_camera/image。IP 是原代码默认值，不代表已连接确认。

尚不能从 SDK 推导：

1. 上楼速度与持续时间。v3.1 中 stair_max_lin_vel 默认 0，flat_stair_runtime.py 还显式设为 0；测试文件演示的是阻止运动。代码没有一段已经验证的上楼时长/距离或自动到平台判据。0.05 m/s 仅可作为低速试验候选，不能称为原项目已验证参数；本交付不自动填入。时间上限到达会停止，但不宣布已到平台。
2. 楼梯入口 x/y/yaw。这是地图里选定的现场预备点，不是 SDK 常数。提供 capture_entry.py，定位就绪后把狗放在准备点并对正，执行一次就保存实际位姿，以后由 Nav2 导航回该点，无需反复手填坐标。
3. /Odometry 的 header.frame_id 和 child_frame_id。离线脚本未核验消息的实际帧名，附件没有 FAST-LIO 源码和已安装工作区；线上程序要求明确给出，且输入须为前雷达 IMU 位姿。先在机器人执行 ros2 topic echo /Odometry --once，不能凭话题名认定 child 就是 base_link。
4. 传感器在同一 ROS 域可见。旧导航隔离域为 73、原厂域 24、离线演示脚本设置 95；本交付不隐式跨域。启动前要在同一域核验全部话题。旧跨域桥可能过滤 map->odom，不能沿用后假定新链路自动可见。
