# 第三阶段现场操作手册

本包完成的流程是：下平台图像初始定位 -> FAST-LIO 连续定位 -> Nav2 走到已测楼梯预备点 -> 停稳并等待确认 -> 调用已经验证的 Stair 上楼程序。上楼时间到只会停止前进，不会自动判断已落地或切换 upper 地图。

## 首次配置

目录已部署到 /home/robot/zhangzhang/d1_stair_nav_phase3_orin_scan_axisfix_20261116；原目录未覆盖。先保持你已经跑通的运行。

    source /opt/ros/humble/setup.bash
    bash scripts/check_dependencies.sh
    bash scripts/build.sh
    python3 scripts/preflight.py --seconds 8
    python3 scripts/preflight.py --write-frames

预检后必须人工确认 /Odometry 仍是 IMU 参考、点云是原始前雷达坐标、标定与实际设备一致。启动：

    bash scripts/run_localization.sh 2>&1 | tee work/localization.log
    bash scripts/run_cloud_scan.sh 2>&1 | tee work/cloud_scan.log

查看地图时使用只读预览，不启动导航控制器：

    bash scripts/run_map_preview.sh floor:=lower

在 RViz 检查 /map、TF、/d1/localization/pose6d、/d1/nav/scan；检查 lower/upper 边缘、未知区、楼梯口、足迹和净空。预览关闭后，狗停在楼梯预备点并对正方向：

    python3 scripts/capture_entry.py --confirm-lower-entry
    python3 scripts/validate_site.py --confirm-map-and-scan

第二条命令只记录操作者已经完成检查。site.yaml 中的速度和时间填写实机已经验证的数值。

## 每次运行

终端一：唯一 SDK 桥，目标 IP 是机器狗 SDK 地址：

    mkdir -p work
    bash scripts/run_stair_bridge.sh 192.168.168.168 0.5 2>&1 | tee work/stair_bridge.log

终端二：Nav2：

    bash scripts/run_nav2.sh floor:=lower 2>&1 | tee work/nav2.log

终端三先做只到入口验证：

    bash scripts/run_mission.sh --live --approach-only 2>&1 | tee work/approach.log

确认狗自动走到入口并停稳后，终端三再运行：

    read -p '请输入最大前进秒数：' STAIR_SECONDS
    bash scripts/run_mission.sh --live --duration "$STAIR_SECONDS" 2>&1 | tee work/mission.log

Nav2 成功后会停止 Nav2 速度转发并切 Stair。提示出现前不会发非零楼梯速度；提示出现后输入：

    y 0.5

其中速度必须不超过桥接端上限。输入错误或不输入会取消。时间到后撤销楼梯许可并发零速度。

## 日志

    tail -n 100 work/stair_bridge.log
    grep -nE 'FAULT|DONE|Stair|WARN|ERROR' work/stair_bridge.log

Watchdog 调度优先级警告通常不是失败原因。重点查看 SDK readiness、控制权、状态序号、Stair 确认、速度许可、视觉状态和 scan_status。首次实机必须有人在旁监督；先完成 approach-only，再做完整交接。
